# 项目目录结构说明

## 1. 说明原则

本文档以当前仓库实际结构为主，同时补充与最新架构文档一致的职责说明。

需要注意：
- 当前前端目录名称是 `frontend-streamlit/`，不是旧文档中的 `frontend/`。
- 当前后端已经有认证、对话、爬虫等实现，但分析任务查询与报告邮件相关接口仍属于后续补充项。
- `docs/2`、`docs/4`、`docs/5` 描述的是统一后的目标设计，代码实现可能仍在逐步对齐。

## 3. 目录职责说明

### 3.1 `backend/`

| 目录/文件 | 职责 |
|------|------|
| `app/main.py` | FastAPI 应用入口，注册路由、初始化数据库、配置中间件 |
| `app/config.py` | 管理数据库连接、模型参数、环境变量等配置 |
| `app/api/` | 对外 HTTP API 路由层 |
| `app/services/` | 业务逻辑层，承接认证、对话、分析、爬虫等业务流程 |
| `app/models/` | SQLAlchemy ORM 模型，映射 MySQL 表 |
| `app/schemas/` | Pydantic 请求/响应结构定义 |
| `app/crawlers/` | 京东商品评论采集和数据清洗 |
| `app/agents/` | 多智能体工作流相关代码的承载目录 |
| `app/db/` | 数据库连接、Session 管理与初始化逻辑 |
| `app/utils/` | 链接提取、日志等公共工具函数 |
| `migrations/` | Alembic 数据库迁移脚本 |
| `data/` | ChromaDB 和 DuckDB 本地数据文件 |
| `tests/` | 后端测试 |

### 3.2 `frontend-streamlit/`

| 目录/文件 | 职责 |
|------|------|
| `app.py` | Streamlit 主入口，承载主页面和整体布局 |
| `config.py` | 前端运行配置 |
| `pages/` | 多页面扩展目录 |
| `components/` | 可复用 UI 组件目录 |
| `utils/api_client.py` | 与 FastAPI 交互的客户端封装 |

### 3.3 `docs/`

| 文件 | 内容 |
|------|------|
| `0.文档统一修订方案.md` | 文档修订口径说明 |
| `1.需求分析.md` | 项目需求与功能边界 |
| `2.系统整体架构图.md` | 系统分层、消息分流、任务链路 |
| `3.项目目录结构.md` | 当前目录与职责说明 |
| `4.数据库设计.md` | MySQL、DuckDB、ChromaDB 的统一设计 |
| `5.API接口定义.md` | 统一消息入口、任务查询和结果接口 |
| `6.爬虫模块设计.md` | 爬虫细化设计，当前预留 |
| `7.邮件与报告模块设计.md` | 邮件投递与报告扩展设计，当前预留 |

## 4. 与新架构对齐的关键约束

1. 当前前端基线固定为 `frontend-streamlit/`。
2. 前端统一通过消息接口发起输入，不在前端层区分普通聊天和商品分析。
3. 后端后续应在 `app/api/` 与 `app/services/` 中补齐分析任务查询、报告邮件发送等接口实现。
4. `products/comments` 属于共享商品数据，`conversations/messages/analysis_tasks/analysis_reports` 属于用户私有数据。
5. 目录文档优先反映当前仓库现状；若实现尚未补齐，以 `docs/2`、`docs/4`、`docs/5` 作为目标设计依据。
