# API 接口定义

> 基础路径：`http://localhost:8000`
> 需要鉴权的接口统一携带：`Authorization: Bearer <token>`
> 当前后端已切换为“统一消息入口 + 任务化分析 + 多 Agent 结果查询”模式

---

## 1. 设计原则

1. 前端只有一个消息发送入口：`POST /api/conversations/{conversation_id}/messages`。
2. 当前实现中，发送消息后统一创建或复用分析任务，不再存在“同步直返普通聊天 reply_message”的接口分支。
3. 前端通过 `task_id` 轮询任务进度，再单独拉取任务结果。
4. 接口统一使用 `ApiResponse[T]` 包装：
   - `code`：业务状态码
   - `data`：响应数据
   - `message`：文本说明
5. `product_id` 表示 MySQL 内部商品主键；平台商品 ID 使用 `external_product_id`。

---

## 2. 通用响应格式

统一响应结构：

```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```

典型错误响应：

```json
{
  "detail": "Conversation not found: 12"
}
```

说明：
- 当前异常场景主要通过 FastAPI `HTTPException` 返回 `detail`，并不总是包装成统一 `ApiResponse`。

### 4.2 获取会话列表

| 项目 | 内容 |
|---|---|
| Method | `GET` |
| URL | `/api/conversations?page=1&page_size=20` |

| HTTP 状态码 | `200` |

响应数据结构：

每个 `items[]` 元素包含：

### 4.3 获取会话详情

| 项目 | 内容 |
|---|---|
| Method | `GET` |
| URL | `/api/conversations/{conversation_id}` |
| 鉴权 | 需要 |
| HTTP 状态码 | `200` |

响应数据结构：
- `id`
- `title`
- `bound_product_id`
- `messages[]`
- `tasks[]`
- `created_at`
- `updated_at`

其中：
- `messages[]` 为消息时间线
- `tasks[]` 为该会话关联的分析任务摘要列表

### 4.4 发送消息

| 项目 | 内容 |
|---|---|
| Method | `POST` |
| URL | `/api/conversations/{conversation_id}/messages` |
| 鉴权 | 需要 |
| HTTP 状态码 | `202` |
| 业务 `code` | `202` |

请求体：

```json
{
  "content": "请分析这款商品的差评，重点看物流和售后问题。 https://item.jd.com/1000001.html"
}
```

当前实现规则：
- 后端先保存用户消息。
- 后端尝试从消息中提取商品链接，或复用会话已绑定商品。
- 后端创建或复用 `analysis_task`。
- 后端通过后台任务异步调度 `AnalysisService.process_task()`。
- 接口立即返回 `user_message + analysis_task`，不直接返回最终分析结论。

响应示例：

```json
{
  "code": 202,
  "data": {
    "user_message": {
      "id": 6003,
      "role": "user",
      "message_type": "analysis_request",
      "content": "请分析这款商品的差评，重点看物流和售后问题。 https://item.jd.com/1000001.html",
      "created_at": "2026-04-20T09:22:00"
    },
    "analysis_task": {
      "task_id": "6c53093a-d40b-4859-bcb0-399a47701ce1",
      "status": "pending",
      "progress": 10,
      "current_step": "resolve_product_context",
      "product_id": 3
    }
  },
  "message": "Analysis task created"
}
```

响应字段定义：

| 字段 | 类型 | 说明 |
|---|---|---|
| `user_message.id` | `int` | 用户消息 ID |
| `user_message.role` | `user \| assistant \| system` | 当前实现这里固定为 `user` |
| `user_message.message_type` | `analysis_request` | 当前发送消息统一落为分析请求类型 |
| `user_message.content` | `string` | 用户原始输入 |
| `user_message.created_at` | `datetime` | 消息创建时间 |
| `analysis_task.task_id` | `string` | 后续轮询使用的业务任务 ID |
| `analysis_task.status` | `pending \| processing \| completed \| failed` | 当前任务状态 |
| `analysis_task.progress` | `int` | 当前进度百分比 |
| `analysis_task.current_step` | `string \| null` | 当前步骤 |
| `analysis_task.product_id` | `int \| null` | 内部商品主键 |

## 5. 分析任务模块 `/api/analysis/tasks`

说明：
- 分析任务不由前端显式创建。
- 前端只通过消息接口触发任务。
- 分析任务模块负责查询进度、拉取结果、重试失败任务。

### 5.1 获取任务状态与进度

| 项目 | 内容 |
|---|---|
| Method | `GET` |
| URL | `/api/analysis/tasks/{task_id}` |
| 鉴权 | 需要 |
| HTTP 状态码 | `200` |
| 业务 `code` | `200` |

响应示例：

```json
{
  "code": 200,
  "data": {
    "task_id": "6c53093a-d40b-4859-bcb0-399a47701ce1",
    "status": "processing",
    "current_step": "sql_agent",
    "progress": 55,
    "steps": [
      {
        "step": "resolve_product_context",
        "label": "解析商品上下文",
        "status": "completed"
      },
      {
        "step": "ensure_product_data",
        "label": "检查商品数据",
        "status": "completed"
      },
      {
        "step": "sql_agent",
        "label": "执行统计分析",
        "status": "processing"
      }
    ],
    "report_ready": false,
    "error_message": null
  },
  "message": "success"
}
```

响应字段：
- `task_id`：任务 ID
- `status`：任务状态
- `current_step`：当前执行步骤
- `progress`：进度百分比
- `steps[]`：步骤级进度视图
- `report_ready`：报告是否已落库，可否拉结果
- `error_message`：失败原因

### 5.2 获取任务结果

| 项目 | 内容 |
|---|---|
| Method | `GET` |
| URL | `/api/analysis/tasks/{task_id}/result` |
| 鉴权 | 需要 |

返回规则：
- 结果未就绪：HTTP `202`，业务 `code=202`，`data=null`
- 结果就绪：HTTP `200`，业务 `code=200`
- 任务失败：HTTP `500`
- 任务不存在：HTTP `404`

## 6. 当前接口与旧协议差异说明

本次按当前代码状态修正了以下过时描述：

1. `POST /api/conversations/{conversation_id}/messages` 不再返回：
   - `handling_mode`
   - `reply_message`
2. 当前实现里发送消息统一进入分析任务链路。
3. `GET /api/conversations/{conversation_id}/tasks` 当前真实存在。
4. `GET /api/analysis/tasks/{task_id}/result` 当前真实返回的是新版结构：
   - `final_response`
   - `route_decision`
   - `sql_result`
   - `visual_result`
   - `rag_result`
   - `answer_draft`
   - `master_decision`
   而不是旧版文档中的：
   - `summary`
   - `statistics`
   - `charts_config`
