# 前端联调模块设计概要

## 模块目标
1. 将 `frontend-streamlit/` 对齐最新后端接口，接入真实登录、会话列表、创建会话、统一消息发送。
2. 在前端展示分析任务状态与分析结果，覆盖 `direct_reply` 与 `task_created` 两种消息处理模式。
3. 接入失败任务重试、会话删除与重命名，形成可自测的前后端联调闭环。
4. 在实现过程中清理前端中已过时的旧 API 调用和无效占位逻辑，但不破坏现有项目结构。

## 约束边界
- 必须遵循 `docs/1-5` 中的统一架构与 API 定义。
- 前端只通过统一消息入口 `/api/conversations/{conversation_id}/messages` 发送用户输入。
- 商品分析任务由后端自动创建，前端只负责轮询 `/api/analysis/tasks/{task_id}` 和读取结果 `/api/analysis/tasks/{task_id}/result`。
- 本模块不实现新的后端业务能力，不重构分析链路，只做前端接入、兼容修正与必要清理。

## 原子功能点拆分
1. 重写前端 API 客户端，对齐认证、会话、任务、重试接口。
2. 重构 Streamlit 状态管理，支持登录态、当前会话、消息列表、任务轮询状态。
3. 实现主聊天页，接入会话列表、创建会话、发送消息、展示消息流。
4. 接入分析任务展示，包括进度、结果、失败提示与重试按钮。
5. 清理旧接口调用和无效占位代码，并完成模块级自测。

## 主要文件
- `frontend-streamlit/app.py` - Streamlit 主入口与页面交互
- `frontend-streamlit/config.py` - 前端配置
- `frontend-streamlit/utils/api_client.py` - 后端接口封装
- `backend/app/api/conversations.py` - 前端依赖的会话接口
- `backend/app/api/analysis.py` - 前端依赖的任务接口

## 实现策略
- 优先复用现有后端接口，不新增前端无必要的抽象层。
- 前端状态以 `st.session_state` 为核心，避免引入额外复杂度。
- 先打通主流程，再补齐删除、重命名、重试等操作。
- 清理旧代码时只移除已确认失效的旧接口调用和占位逻辑，保留仍被当前模块使用的公共配置。
